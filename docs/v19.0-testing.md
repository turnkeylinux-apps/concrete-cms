# Concrete CMS 19.0 testing

## Scope and source decision

Debian 13 Trixie does not package Concrete CMS. The appliance therefore uses
the official Concrete CMS 9.5.2 release asset. The build pins the release at
upstream tag commit `72f0bf37601073e29b279415be8ea2b6af06efac` and verifies
the archive against the SHA-256 published by GitHub for that asset:
`44ba6f6f23ae19b936f6df9652af07590ef2da64933f24095a9a5e807ce553bb`.

PHP 8.4, Composer, Apache, MariaDB, and the required PHP extensions come from
signed Debian Trixie repositories. The official release archive includes the
locked runtime dependencies produced by Concrete CMS.

Concrete CMS retains its supported supervised update paths. Administrators
can use Dashboard > System and Settings > Update Concrete or stage an official
core release and run `turnkey-concrete c5:update`. An upgrade requires a
backup, extension compatibility review, and the upstream release notes. The
acceptance test checks the CLI update command and discovers the current
official release and its published asset digest without changing the site.

## Acceptance command

```sh
/sandboxed-git/turnkey/tools/test-v19-appliance concrete-cms \
    --source /home/agent/.local/worktrees/turnkey-apps/concrete-cms/wish-concrete-cms-v19-trixie
```

The command builds the Trixie root filesystem, imports it into Docker, boots
the normal systemd and firstboot path, then runs `tests/v19.sh`.

## Known limitations

Docker runtime validation does not exercise the installer, kernel, bootloader,
or physical hardware. Concrete CMS adds no appliance-specific behavior at
those boundaries, so the validated Core 19 baseline supplies inherited
evidence.

The page round trip uses Concrete CMS's application service to perform the
administrator-authored page mutation after separately proving the real HTTP
administrator login. It does not automate the browser's JavaScript page
composer, but it exercises the same page, block, version, path, database, and
public rendering layers used by that normal workflow.

The acceptance test does not apply an update to the disposable site. Concrete
CMS upgrades can modify the database and require extension compatibility
review, so the test limits itself to the non-mutating discovery and command
checks appropriate before an administrator-approved maintenance window.

## Deferred minor issues

The inherited firstboot secret hook filename still uses the former Concrete5
product name. Its numeric ordering and behavior remain correct, so this
